# Диагностика

[← Главная](../README.md)

## Быстрая проверка установки

Полностью перезапустите игру после замены DLL. Проверьте:

1. Открывается меню Enshwick, мод включён.
2. Мир открыт через Host на компьютере с модом.
3. В новом логе есть версия `probe=0.6.1`.
4. Нужные проверки совместимости завершились с `status=0`.

Если лог показывает старую версию, повторите сборку и установку с `--replace`
при закрытой игре. Проверьте, что выбран каталог той Steam-библиотеки,
из которой игра действительно запускается.

## Проверки совместимости

| Строка | Что проверяется |
| --- | --- |
| `sprint_patch_registered status=0` | Загрузчик принял патч спринта; выполнение подтверждает счётчик пропусков |
| `cost_trace_hook status=0` | Установлен перехват прямых расходов |
| `action_cost_guard status=0` | Проверены точки расходов прыжков и инструментов |
| `respawn_guard status=0` | Доступны схемы и подписки восстановления при возрождении |
| `climb_trace_hooks status=0` | Включено диагностическое измерение системы лазания |

Ошибки `sprint_patch_guard`, `sprint_patch_body`, `action_cost_sites` или
`respawn_guard` означают отказ соответствующей функции. Причиной могут быть
другая сборка EXE, изменённые инструкции, конфликт модов или недоступный API.
Проверки не обходите: приложите свежие логи.

Предупреждение Enshwick E1005 о неполной таблице само по себе не означает,
что весь мод выключен: проверенные сборки /205 и /210 допускают PATTERNS. Решение
каждой функции видно по её guard. Другие сборки автоматически не принимаются.

## Расход спринта, прыжков и инструментов

`sprint_player` пишет условия и интервальные счётчики отдельно для каждого
слота. `allowed=1` — разрешение вне обнаруженного боя; `skipped>0` — реальные
пропуски. `ai_combat_target=1` и `cooldown_ms` объясняют блокировку.
`ai_candidate=1` без боевой цели не должен сам запускать задержку.

`cost_trace` показывает исходную `delta` и применённую `applied_delta`.
При подавлении: `forwarded_unchanged=false applied_delta=0`.

| action_reason | Значение |
| --- | --- |
| 0 | Неподдержанный путь или выключенная новая часть: обычная стоимость |
| 1 | Бесплатное действие инструмента |
| 2 | Бесплатный наземный прыжок |
| 3 | Не подтверждён серверный поток |
| 4 | Не совпал живой компонент игрока |
| 5 | Истёк кэш игроков |
| 6 | Недоступны схема, компонент или API предмета |
| 7 | Нет свежего разрешения прыжка вне боя |
| 8 | Исключённый, неизвестный или недоступный тип прыжка |
| 9 | Нет item ID или данных item_info |
| 10 | Не подходит категория предмета |
| 11 | Не подходит или недоступна анимация |

`action_detail` содержит тип запрошенного прыжка или item ID в зависимости
от пути. Величина -3/-10 сама по себе не определяет действие.

Отсутствие `climb_trace` не является ошибкой: измеренный участок мог не
выполняться для распознанного игрока. `changed>0` означает изменение
накопителя на измеренном участке; before/after — сырые биты float32 последней
пары измерений. Эта диагностика не отменяет стоимость лазания.

## Не восстановились ресурсы при возрождении

Ожидаемый порядок:

```text
respawn_guard status=0
respawn_death entity=...
sample ... respawn_refill slot=... entity=... health=...->... stamina=...->... mana=...->...
```

`respawn_wait` объясняет ожидание: `dead_health`, `actor_not_alive`,
`resources_unavailable` или `character_missing`. `respawn_write` означает
отказ проверки writable-компонентов; до успешной проверки всех трёх
ресурсов значения не записываются.

`respawn_cancel_left` отменяет ожидание при выходе, `respawn_expired` — после
неудавшегося окна записи. Смена мира очищает ожидания. Если нет `respawn_death`,
смерть могла не попасть в поддерживаемые события. Простое подключение
пополнение не запускает.

## Что прислать при проблеме

Из `Enshrouded/logs/` приложите **два свежих файла одной сессии**:

- `enshwick_*.log`;
- `hitmanrec.stamina-probe_*.log`.

Добавьте версию мода, описание проблемного действия и кто его делал — хост
или гость. Полезны примерное время/порядок действий, оружие/инструмент и наличие
врагов. Полный повтор всех прошлых тестов не нужен.

Перед публикацией проверьте лог загрузчика: он может содержать пути и сетевые
идентификаторы. Логи прикладывайте к сообщению или обсуждению, **не коммитьте
в репозиторий** — они исключены через `.gitignore`.

После обновления игры может понадобиться новый read-only отчёт EXE.
Команда и ограничения инструмента описаны в [разработке](development.md#новая-сборка-игры).
