# Сессия 0.4.3 с двумя гостями: патч отказался от новой сборки

Источники: оба лога `2026-11-03_14-32-04` в `logs/`.

Стартовый fingerprint: `e378da3d6079c049b30cd1604a0e7846`, age 205,
`build_table=1`. Ранее проверялся `69f0e9573b32c24a8838d3fff550824c`, age 520,
с точной таблицей. Загрузчик сообщает E1005: новая сборка ещё без таблицы,
используется поиск по engine routes/patterns, три записи отсутствуют.

Наши проверки штатно отказали:

```text
cost_trace_guard status=3
sprint_patch_guard status=3
```

| Участник по порядку появления | slot | entity | loader_channel_status | allowed | Сумма skipped |
| --- | --- | --- | --- | --- | --- |
| Хост | 0 | 1 | 0 | 0 | 0 |
| Первый гость | 1 | 2 | 1 | 0 | 0 |
| Второй гость | 2 | 3 | 1 | 0 | 0 |

Таблица построена по всем строкам sprint_player этой сессии. Патч не был
включён ни у кого: это не отказ разделения игроков и не доказательство
невозможности работы только на хосте. Отсутствие готового канала Enshwick
у обоих гостей согласуется с тестом без загрузчика. Серверные компоненты
игроков читаются; но подавления расхода и работы client prediction этот
прогон не проверяет.

Обнаруженные адреса stamina_depletion_sprint и других систем остались прежними.
Это полезный ориентир, но не подтверждение идентичности инструкций, ABI
или семантики новой сборки. Убирать проверки fingerprint/таблицы нельзя.

Следующий шаг не требует приглашать гостей или запускать игру: снять
статический отчёт текущего EXE штатным read-only инструментом.

```sh
python3 scripts/inspect-game.py \
  --exe "$HOME/.local/share/Steam/steamapps/common/Enshrouded/enshrouded.exe" \
  --out .build/build-e378da3d-205 --max-functions 512 \
  --focus-rva 0x2f1000 --focus-rva 0x21fbc0 --focus-rva 0x379210
tar -C .build -czf new-build-report.tar.gz build-e378da3d-205
```

Для другой библиотеки Steam подставить её путь. Нужны Python и objdump
(Arch: пакет binutils). Каталог отчёта должен быть новым/пустым. Значение
`Fingerprint matches probe logs: False` ожидаемо: эта строка инструмента
сравнивает с исходной проверенной сборкой, а не с самым свежим логом.
Архив содержит отчёт/дизассемблирование, не сам EXE. После проверки кода
можно добавить явно поддержанную новую сборку и только затем повторить
совместный тест. По этой сессии игровой код не менялся.
