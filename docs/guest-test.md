# 0.4.3: исправление целей ИИ и проверка гостя без мода

## Что исправлено

Ранее любая из 16 записей SelectedTargets, ссылавшаяся на игрока, запускала
блокировку. Теперь её запускает **элемент 0**, который исследование
`enemy_combat_targets` связывает с выбранной боевой целью, а также входящие
и исходящие HitEvent. Остальные элементы только логируются. Фракция 07 не
исключается целиком: её номер сам по себе не доказывает отсутствие агрессии.
Попадания, задержка 10 секунд и отказ при неполных данных сохранены.

Источник — [EMF Engine Map, Enemy AI](https://github.com/matenm/emf-enshrouded/blob/7d014b2d42cb63196fe147a389ed13dea69d1f6d/docs/ENGINE_MAP.md#24-factions-and-combat-damage),
абзац перед разделом 2.4: `enemy_combat_targets` RVA `0x379210`, winner in
`SelectedTargets[0]`. [Сгенерированные компоненты](https://github.com/matenm/emf-enshrouded/blob/7d014b2d42cb63196fe147a389ed13dea69d1f6d/sdk/include/emf/generated/components.hpp)
указывают SHA-256 `0403981fd2e8ad18bd8c5698dff03c8d505b5a46677832c496db9c645513f2a6`,
совпадающий с присланным EXE. В сессии 0.4.0 бой с волками действительно давал
`primary_slot_mask=1`; ошибочные блокировки сессии 0.4.2 были при нуле.

Это уточнённый детектор по игровому выбору цели, а не проверенный универсальный
флаг боя. Начало агрессии до выбора боевой цели, исчезновение/смена цели,
фактическое поведение разных существ и задержка опроса до 250 мс ещё требуют
проверки. Новая версия не обещает, что любой элемент 0 означает враждебность
у каждого возможного владельца компонента.

## Подготовка

Полностью закрой игру и обнови установленный мод **на хосте**:

```sh
git pull --ff-only
sh scripts/build-probe.sh
python3 scripts/install-probe.py \
  --game-dir "$HOME/.local/share/Steam/steamapps/common/Enshrouded" --replace
```

Если библиотека Steam на другом диске, подставь её путь. Сохрани резервную
копию мира. Гостю для первой проверки **ничего не устанавливать**: проверяем
именно действие мода только у хоста. Не устанавливай ему загрузчик даже для
сбора логов на этом этапе — это изменит условие теста.

Enshwick по умолчанию требует загрузчик у гостей. В уже созданном файле
`<save>-mod-settings/enshwick/enshwick.toml` нужного мира установи при закрытой
игре:

```toml
require_enshwick = false
```

Сохрани остальные настройки. Файл лежит рядом с сохранением мира, а не в
каталоге установки игры. Другие моды на время проверки убери. Если гость не
подключается, сохрани ошибку и лог загрузчика; не устанавливай ему мод для
обхода ошибки до проверки причины.

## Один совместный прогон

Оба игрока начинают в безопасном месте, без прыжков, планера и инструментов.
Желательно записать экран гостя: серверный запас стамины не показывает, что
видит клиент и не прерывает ли он спринт из-за собственного предсказания.
Можно вместо видео записать порядок и примерную длительность этапов, плюс
заметки гостя об индикаторе и возможности продолжать бег.

1. Хост открывает мир один и стоит 10 секунд. Затем гость подключается,
   оба стоят ещё 15 секунд. Так по журналу видно, какой слот принадлежит хосту,
   а какой появился у гостя; слот 0 не считается хостом автоматически.
2. Хост спринтит 15 секунд с пустым слотом, гость стоит. Пауза 15 секунд.
3. Гость спринтит 15 секунд с пустым слотом, хост стоит. Пауза 15 секунд.
4. Повторите пункты 2–3 с жезлом, чтобы сравнить оружие при одинаковых условиях.
5. Хост привлекает одного врага, получает один удар и спринтит. Гость остаётся
   достаточно далеко, чтобы враг его не выбирал, и тоже пробует спринт.
   Запишите, кто был целью врага и получил удар. После ухода от врага подождите
   хотя бы 15 секунд вне агрессии.
6. Поменяйтесь ролями: теперь только гость в бою, хост спринтит в безопасном
   месте. После ухода от врага снова пауза 15 секунд.
7. Гость выходит. Хост стоит 10 секунд. Гость подключается заново и спринтит
   10 секунд вне боя. Затем оба заканчивают сессию.

Если сложно надёжно изолировать одного игрока от врага, отметьте это, не
считайте такой этап доказательством ошибки разделения боя. Само нахождение
рядом с волком до первого удара тоже стоит отметить: это проверяет раннюю
агрессию. Не нужно многократно драться или собирать ресурсы.

## Что прислать

Два свежих файла из `Enshrouded/logs/` хоста:
`enshwick_*.log` и `hitmanrec.stamina-probe_*.log`, с `probe=0.4.3`.
Добавь описание этапов/время или видео гостя. Достаточно названий «хост» и
«гость»; имена, аккаунты и IP нам не нужны. Перед публикацией проверь лог
самого загрузчика — он может содержать пути и сетевые идентификаторы.

## Как читать новые строки

- `sprint_player slot=… entity=…`: отдельная строка для каждого игрока раз в
  heartbeat (~5 секунд) и при изменении разрешения/наблюдаемых целей.
  `allowed`, `pointer_valid`, `event_ready`, `ai_complete` показывают условия.
  `ai_candidate=1 ai_combat_target=0` теперь **само по себе не блокирует** спринт.
- `cooldown_ms`: оставшаяся задержка; `combat_hits`: число событий попаданий,
  вызвавших блокировку данного игрока с предыдущей его строки.
- `matches`, `skipped`, `deny_selector`, `deny_permission`, `expired`,
  `combat_blocked`: отдельные интервальные счётчики, только для его накопителя.
  Данные гостя не складываются с хостом. `skipped>0` означает реальный пропуск
  в серверном компоненте; не является доказательством поведения UI гостя.
- `loader_channel_status=0`: клиент принимает сообщения Enshwick, **не**
  доказательство установки нашего мода. `1` означает отсутствие готового
  канала; для гостя без загрузчика это ожидаемо. Имена/ключи аккаунтов не пишутся.
- `sprint_player_left`: слот перестал присутствовать, разрешение и указатель
  удалены. При повторном входе новый персонаж получает собственные счётчики.
- `ai_target_indices`: владелец ИИ, слот игрока и битовая маска индексов
  SelectedTargets. Бит 0 соответствует боевому элементу; остальные — наблюдения.
  `ai_target_detail` добавляет индекс и отражённые `flags`/`importance` либо
  `unavailable`. Их биты пока не интерпретируются как готовый флаг боя.
- Существующие строки `stamina_status` отражают запас **на сервере** по entity;
  строки `sprint_player` связывают entity со slot. Поля движения/экипировки,
  события попаданий и observer расходов также сохранены для обоих игроков.

Ожидается: вне боя разрешены оба игрока, в изолированном бою блокируется
только участник; спустя 10 секунд без боевой цели/попаданий разрешение возвращается.
При неполном обходе ИИ бесплатный спринт остаётся выключенным. Прыжки, планер
и инструменты по-прежнему имеют обычный расход. Если серверный запас гостя
не падает, а его клиент всё равно останавливает спринт/показывает расход,
тогда потребуется отдельно решать клиентское предсказание; обещать работу
для всех без установки до этого прогона нельзя.
