# Проверка 0.4.2: спринт работает до блокировки по целям ИИ

Источники: оба лога `2026-11-03_13-55-46` в `logs/`.
Пользователь сообщил короткую задержку расхода с жезлом и значительно более
длинный спринт после переключения на пустой слот.

Серверная стамина и счётчики подтверждают:

| Время UTC | Наблюдение |
| --- | --- |
| 13:56:19.554–20.853 | Разрешение включено, пропускаются 12–16 списаний за опрос |
| 13:56:21.121 | AI 1354: player_slot_mask=1, primary_slot_mask=0, faction_raw=07; разрешение выключено |
| 13:56:21.387 | Первое уменьшение с 138 до 137, далее обычный расход |
| 13:56:30.454 | primaryAnimationSet меняется с 07 на 00; пользователь связывает это с пустым слотом |
| 13:56:38.971 | Разрешение снова включено, стамина 138/138 |
| 13:56:40.004–53.288 | Списания пропускаются постоянно; снимки 13:56:44.155 и 49.388 остаются 138/138 |
| 13:56:53.555 | AI 1358: те же маски и faction_raw=07; разрешение выключено |
| 13:56:53.821 | Стамина падает до 136, затем расход продолжается |

Таким образом, исправление селектора имеет игровой эффект: серверная стамина
не уменьшается при разрешённом спринте. Разная продолжительность двух проб
объясняется разным временем блокировки наблюдением ИИ; отдельный расход
спринта из-за жезла по этому прогону не доказан. Задержка индикатора согласуется
с отсутствием расхода, но сам интерфейс логом не измеряется.

Цели ИИ здесь не являются доказательством агрессии: primary_slot_mask=0,
enemy_component_status=1 означает отсутствие именно проверяемого компонента,
а не отсутствие врага вообще. faction_raw=07 без проверки отношений тоже
не классифицирует цель как дружественную или враждебную.

Следующая проблема — классификация наблюдений SelectedTargets. Сейчас любая
ссылка на игрока запускает 10-секундную блокировку. Простая замена на элемент
0 или исключение всей фракции 07 без проверки семантики может пропустить
реальный бой. Следует исследовать назначение записей TargetInfo и отношение
владельца к игроку; сохранять блокировку по реальным попаданиям.
Расширять подавление на неизвестные указатели для объяснения этой сессии
не требуется: начало расхода совпадает с явной блокировкой серверного игрока.

По результатам этой сессии игровой код не изменён. Повторять такой же прогон
или переустанавливать 0.4.2 пока не нужно.
