# Разбор сессии 0.3.0: прыжки, склон и инструменты

Источники: коммит `88af769`, два лога `2026-11-03_12-27-46` и порядок действий,
сообщённый пользователем в чате. Точные метки отдельных этапов отсутствуют;
привязка последовательности к окнам ниже основана на порядке и событиях.
Времена таблиц — UTC исходного лога; местное время пользователя UTC+5.

## Условия прогона

После входа пользователь телепортировался домой, постоял, спринтил после
разгона, снова постоял, делал двойные прыжки без полного восстановления.
Далее добежал до горы: сначала одиночные прыжки вверх по почти отвесному
проходимому склону, затем две серии спама прыжков/двойных прыжков до истощения.
После паузы — дерево (три удара и три попытки взмаха). По пути к породе
спринт/прыжки и атаки крыс. Затем восстановление, три удара по кремнию,
пауза, два удара по предположительно земле и три попытки взмаха в воздух.
Все серии инструментов выполнялись **удержанием ЛКМ**, не отдельными кликами.

Последний участок нельзя считать чистым контролем вне боя: рядом действительно
есть входящие попадания. Попытка взмаха/ввод не гарантирует выполненную
анимацию и стоимость, особенно при удержании кнопки или нулевой стамине.

## Observer работает в реальной игре

`probe=0.3.0`, `cost_trace_hook status=0`, EXE build `26320373`, GUID/age
совпадают с офлайн-отчётами. Есть 42 записи, сопоставленные с Stamina игрока:

| Return RVA | Дельта | Количество |
| --- | --- | ---: |
| `0x2C97F9` | -10 | 16 |
| `0x2C97F9` | -15 | 12 |
| `0x223B0F` | -3 | 13 |
| `0x223B0F` | -4 | 1 |

`dropped=0`: переполнение/конкуренция очереди не потеряли наблюдения.
Ещё 52 записи не сопоставлены с живым авторитетным контейнером игрока.
Нельзя объявлять их все NPC или потерянной стаминой: возможны иные контейнеры,
предсказание клиента, смена сущности или другие причины. Нужно отличать
переданную стоимость от итогового изменения запаса после формул/регенерации.
Лог загрузчика завершён сообщением о штатной остановке hosted world.

## Имена систем теперь подтверждены API игры

| Reflected system | RVA |
| --- | --- |
| `stamina_depletion_sprint` | `0x2F1000` |
| `stamina_depletion_glider` | `0x2F0CE0` |
| `stamina_depletion_climb_wall` | `0x2F0600` |
| `stamina_depletion_finalize` | `0x2F0A90` |
| `stamina_recharge` | `0x23DB80` |
| `player_control_action_sequence` | `0x2DCBC0` |

Важная коррекция офлайн-гипотезы: векторный расчёт `0x2F0600`, прежде
названный кандидатом стоимости движения, — **climb_wall**, не sprint/glider.
Его нельзя использовать как перехват спринта. Прямое целочисленное списание
`0x2F0C79` действительно находится в finalize. Поиск по одному литеральному
хешу Stamina не экспортировал тела sprint/glider, поскольку они могут работать
с накопителем без такого литерала.

## Прыжки и склон

- В 12:30:21.713, 12:30:24.548 и 12:30:27.164 записаны три стоимости **-10**
  из `0x2C97F9`, рядом с переходами Walking → Falling → Walking. Это совпадает
  с последовательностью двойных прыжков по описанию пользователя.
- В 12:31:19–12:31:22 идут стоимости -15 и -10 из того же call site.
- В 12:32:03–12:32:19 идёт ещё серия -15/-10; запас в этом окне достигает 0.
  По порядку это попытки прыжков/двойных прыжков на склоне до истощения.

Подтверждено, что у наблюдавшихся прыжковых расходов общий вызывающий путь
с двумя стоимостями. Но сам return RVA **не доказывает**, что путь обслуживает
только прыжки: в нём могут использоваться разные cost-items/действия. Числа
10/15 также нельзя использовать как единственный классификатор. Названия
`defaultJumpCostItem`/`struggleJumpCostItem`, найденные в EXE, согласуются
с гипотезой разных прыжковых стоимостей, но их привязка к этим вызовам пока
не установлена. Обычный прыжок остаётся бесплатным по сведениям пользователя.

## Инструменты и попадания

В 12:33:02–12:33:04 три стоимости **-3** через `0x223B0F` совпадают с тремя
попаданиями игрока по одной цели, `weaponPideId=8574`, `damageTypes=0x200`
(wood в исследованном enum), `attackCategory=9`. Это сильная привязка к
топору и дереву. Затем есть две стоимости -3 без соответствующих попаданий,
что согласуется со взмахами в воздух; третью попытку нельзя объявлять
выполненным действием только по описанию удержания кнопки.

В 12:34:58–12:34:59 идут три mining-попадания с `weaponPideId=8575`,
`hasMiningVolume=1`, target 0, и три стоимости -3 из того же `0x223B0F`.
По описанию материал — кремень. Это не проверка металлической руды.
Ближе к 12:35:22–12:35:23 есть ещё два попадания этим инструментом, но уже
без miningVolume и с wood damage channel. **По одному damageTypes нельзя
назвать материал или инструмент**: здесь кирка и предположительно земля
используют тот же channel, что у дерева. После этого три стоимости -3
без попаданий совпадают с тремя попытками взмаха в воздух.

Итого: расход идёт через общий обработчик стоимости раньше/независимо от
HitEvent. Обнулять весь call site `0x223B0F` или любую стоимость -3 нельзя:
это может сделать бесплатными боевые атаки или другие действия. `weaponPideId`
— идентификатор сущности в этой сессии, а не постоянный ID типа кирки/топора.
Отдельная стоимость -4 в 12:32:05 пока не получила надёжной классификации.

## Крысы и лечение

Есть входящие попадания по игроку в 12:33:56 и 12:34:14–12:34:20. Между ними
видны события игрок → тот же игрок с `healthChange=+16`, флагом **0x4000**:
это healing flag, не атаки врагов и не повод продлевать боевой таймер.
Будущая классификация должна исключать лечение, но учитывать блокированные
атаки без потери здоровья. Сама пауза/восстановление запаса не доказывает
исчезновение агрессии.

## Следующая работа без повторения этого прогона

Данных достаточно, чтобы продолжить реализацию различения путей. Нужны:

1. Для sprint — отдельный идентифицированный system, а не отключение finalize,
   которое затронуло бы планёр/лазание и другие накопленные расходы.
2. Для прыжков — cost-item или идентичность действия в общем обработчике,
   чтобы не опираться только на число стоимости/return address.
3. Для инструментов — действительный тип предмета и контекст gathering,
   отличающий его от боя; HitEvent приходит не всегда и может быть позже дебета.
4. Для боя — враждебные цели и корректно отфильтрованные события, с отдельным
   состоянием каждого игрока и сохранением обычного расхода при неизвестности.

Новый полный игровой прогон сейчас не нужен. Скидки на стоимость в 0.3.0
по-прежнему не включены. Host-only действие для гостей ещё не проверялось.
