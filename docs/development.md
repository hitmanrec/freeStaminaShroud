## Структура

```text
probe/                    C11-реализация Windows DLL
  probe.c                 manifest, инициализация и серверный tick
  builds.h                список проверенных сборок и digest спринта
  sprint.h, sprint_stub.h  патч накопления расхода спринта
  actions.h               живое определение инструмента и запроса прыжка
  cost_trace.h            перехват и ограниченная очередь прямых расходов
  respawn.h               однократное пополнение после смерти/оживления
  diagnostics.h           отражение компонентов, ИИ, события и чтение стамины
  climb_trace.h           read-only измерение накопления расхода лазания
  entry.c                 DLL entry без CRT и работы под loader lock
scripts/                  сборка, установка, тесты и read-only анализ EXE
tests/                    native fake-host и Python-проверки
third_party/enshwick/      закреплённый C SDK и MIT-лицензия
```

Имя `stamina_probe.dll`, ID `hitmanrec.stamina-probe` и имена существующих
скриптов сохранены для совместимости с установленными версиями. DLL содержит
игровые функции; слово probe осталось от начальной диагностики.

## Сборка и проверки

Нужны x86-64 Linux, C-компилятор, Python 3 и Zig. Проверен Zig **0.14.1**.

```sh
sh scripts/test-all.sh
sh scripts/build-probe.sh
```

`test-all.sh` запускает native тесты **реального C-кода** и Python-тесты
установщика/PE-анализатора. Отдельного неиспользуемого C++-прототипа больше нет.

Native проверки покрывают решения о стоимости, переключение предметов между
опросами, разные игроки/слоты, неверные потоки, истечение кэша, неизвестные
атрибуты/вызовы, обе исполняемые ветки машинного stub, границы чтений и
однократное восстановление после возрождения. Дополнительно при изменении
работы с памятью полезен ASan/UBSan, например:

```sh
cc -std=c11 -Wall -Wextra -Werror -pedantic \
  -fsanitize=address,undefined -fno-omit-frame-pointer \
  -I third_party/enshwick tests/respawn_test.c -o .build/respawn_sanitized
.build/respawn_sanitized
```

Windows DLL собирается freestanding, с четырьмя Enshwick ABI-экспортами.
Импорты ограничены KERNEL32: таймер, ID потока и управление памятью. Саму игру
в облачной среде не запускали; native проверки не заменяют игровой прогон.

## Совместимость

Enshwick C SDK закреплён на commit
[`535efb4944f99b84de6c5cd12378042b0485d3dc`](https://github.com/enshwick/enshwick/tree/535efb4944f99b84de6c5cd12378042b0485d3dc), ABI **11.1**.
Контрольные суммы — в `third_party/enshwick/SHA256SUMS`.
Проверенный архив загрузчика имеет SHA-256:

```text
f6ceb5b93bf0e659f95e1f75b67c578b38b6ac1b510a0027999380e2ab3de7ec
```

Поддерживается клиентский EXE со встроенным сервером:

| CodeView GUID, little-endian | Age | Режим таблицы |
| --- | --- | --- |
| `69f0e9573b32c24a8838d3fff550824c` | 520 | EXACT |
| `e378da3d6079c049b30cd1604a0e7846` | 205 | EXACT или PATTERNS |

SHA-256 исследованных EXE:

- /520: `0403981fd2e8ad18bd8c5698dff03c8d505b5a46677832c496db9c645513f2a6`;
- /205: `ce6fdba63e27744943b695921383a29133285d359e07671f6ca33a47e2147618`.

Неизвестный fingerprint не принимается автоматически. Проверяются диапазоны
.text, адреса систем, прологи и окна инструкций. FNV-1a — дополнительный
детектор изменения кода, **не** криптографическая проверка подлинности EXE.

## Точки интеграции

| Назначение | RVA / проверка |
| --- | --- |
| Система спринта | `0x2f1000`; полный диапазон `[0x2f1000,0x2f15b3)` |
| Пропуск накопления спринта | `0x2f1505`, 8 байт ADDSS/MOVSS; возврат `0x2f150d` |
| Общий helper изменения атрибута | `0x21fbc0`, CALLER_FRAME |
| Возврат после прямого расхода действия | `0x223b0f` |
| Возврат после прыжкового расхода | `0x2c97f9` |
| Запись запроса типа прыжка | `0x2c9695`; окно `[0x2c9684,0x2c969b)` |
| Измерение climb_wall | до `0x2f09f6` и после `0x2f09fe` |

Digests спринта: `0xc01aa88c` (/520), `0x40862718` (/205).
Окна действий: `[0x223af7,0x223b0f)` → `0xdec87622`,
`[0x2c97d0,0x2c97f9)` → `0xec1d643e`,
`[0x2c9684,0x2c969b)` → `0x75f3353c`.
Окно climb trace: `[0x2f09f2,0x2f0a04)` → `0x8a76d895`.

Спринт пропускает добавление только для свежего известного накопителя игрока
и селекторов 0/4 в этой конкретной системе. Stub сохраняет регистры/флаги,
соблюдает Windows x64 ABI и возвращается в исходный цикл. После регистрации
его память живёт до конца процесса; обновление требует перезапуска игры.

Прямой расход подавляется только для отрицательной дельты Stamina
`0x04b6aa8b` и двух проверенных вызывающих путей. В оригинальный helper
передаётся delta=0; неизвестные пути и другие атрибуты сохраняются.
На подтверждённом серверном потоке заново читаются текущий предмет/его данные
или `ActorInput.externalTriggerJumpType`. Предыдущее `DynamicLocomotion.jumpType`
для классификации не используется. Workers и клиентское предсказание не
получают разрешение на ECS-чтения из этого перехвата.

Кэш действует 350 мс при опросе раз в 250 мс. Разрешения боя — по каждому
игроку: выбранная цель ИИ в элементе 0, попадания, задержка 10 секунд.
Healing flag `0x4000` исключён. События обрабатываются до ограничения частоты
диагностических строк, чтобы ограничение вывода не теряло игровые решения.

Возрождение отслеживается по ключу подключённого игрока и подтверждённым
событиям смерти. Положительное здоровье, текущий collider mode и два стабильных
снимка максимумов предшествуют записи через `component_write`. Сначала
проверяются writable-представления всех трёх контейнеров; затем меняются только
их текущие значения. Отложенного возврата затрат и постоянного баффа нет.

## Новая сборка игры

Не меняйте GUID/age в allowlist без проверки кода. Сначала соберите отчёт
локального EXE; инструмент читает файл и не запускает игру:

```sh
python3 scripts/inspect-game.py \
  --exe "$HOME/.local/share/Steam/steamapps/common/Enshrouded/enshrouded.exe" \
  --out .build/new-build-report --max-functions 512 \
  --focus-rva 0x2f1000 --focus-rva 0x21fbc0 --focus-rva 0x2c8f60 \
  --focus-rva 0x223860 --focus-rva 0x2f0600 --focus-rva 0x379210
tar -C .build -czf new-build-report.tar.gz new-build-report
```

Подставьте путь своей библиотеки и используйте новый/пустой каталог вывода.
Нужен `objdump` из binutils. RVA выше — ориентиры предыдущей сборки, не
доказательство новых точек. Проверьте пропущенные функции и найденные диапазоны.
`Fingerprint matches probe logs` пока сравнивает с исходной сборкой /520;
False для другой сборки ожидаем и не заменяет ручную проверку.

Сравните стек/ABI, операнды, корневые атрибуты, вызывающие пути и смысл полей.
Добавляйте поддержку конкретной сборки с положительными и отрицательными
проверками, затем выполняйте native тесты, сборку и игровой прогон.

в исходники не коммитьте; используйте `.build/` и вложения к обсуждениям.
