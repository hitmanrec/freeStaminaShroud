# Одиночная диагностика 0.2.1

После полученных сессий найденные ошибки reader исправлены. См.
[разбор данных](session-02-analysis.md). Повторять весь сценарий сейчас не
требуется. При потере фокуса у пользователя наблюдались зависания; перед
дальнейшим захватом следует выбрать способ аннотирования без постоянных
переключений в терминал, например запись игры с последующей шкалой действий.

Гость не нужен. Цель — сопоставить агрессию врага, реальные попадания, добычу,
движение и запас стамины. Мод остаётся read-only; не делает расходов бесплатными.
Полнота диагностики зависит от доступности полей/API, что будет отражено в логе.
Host-only влияние на гостей этим одиночным прогоном не проверяется.

## Обновление

Закройте игру. Из репозитория выполните:

```sh
git pull --ff-only
sh scripts/test-all.sh
sh scripts/build-probe.sh
GAME_DIR="$HOME/.local/share/Steam/steamapps/common/Enshrouded"
python3 scripts/install-probe.py --game-dir "$GAME_DIR" --replace
```

При другой Steam-библиотеке измените `GAME_DIR`. Enshwick и launch option
`WINEDLLOVERRIDES="powrprof=n,b" %command%` остаются прежними.
Повторно скачивать загрузчик для этой версии не нужно: ABI остаётся 11.1.
Установщик сохраняет прежнюю DLL перед заменой.

Откройте мир через **Host**, без других модов. В новом логе probe должна быть
строка `probe=0.2.1 read_only=true`. Проверьте также `stamina_schema status=0`,
`ai_schema status=0`, `event_catalog status=0`. Отсутствующие поля не мешают
остальным наблюдениям; сохраните такие ошибки. Если есть только init без
`sample`, тест игровых действий пока не даст полезного результата.

## Метки действий

Чтобы не восстанавливать последовательность приблизительно, в отдельном
терминале из репозитория запустите:

```sh
python3 scripts/record-solo-session.py
```

Скрипт проводит по этапам: Enter отмечает начало, после действия вернитесь в
терминал и нажмите Enter для конца. Можно написать короткое примечание:
«получил удар во время AGGRO», «руда: медь», «кирка сломалась» и т. п.
Переключение окон входит в интервал; отметьте случайные действия/паузу.
Скрипт ничего не нажимает в игре и не читает её память.

Если удобнее собственный порядок, отдельная метка записывается так:

```sh
python3 scripts/record-solo-session.py --mark AXE_TREE_BEGIN
```

Метки пишутся в `.build/session-markers.tsv`, UTC, как и игровые логи.
Файл дополняется, предыдущие сессии не стираются. Можно задать другой путь
через `--output`. Для каждого автоматического запуска есть отдельный `run`.

## План действий

Переходите к дереву/руде/врагам **между** отмеченными этапами, чтобы дорога
не смешивалась с измерением. Выберите слабого обычного врага. Если агро,
получение урона и атаку не удалось разделить, просто отметьте это — не нужно
повторять сессию целиком. Ориентировочно 10–15 минут, включая перемещения.

| Этап | Что сделать |
| --- | --- |
| `IDLE` | Без врагов спокойно стоять 15 секунд. |
| `EQUIP` | Выбрать оружие, топор и кирку по очереди, по 5 секунд, без атак. |
| `SPRINT` | Спринт 10 секунд по земле, затем простой 15 секунд. Без прыжков и планера. |
| `JUMP` | Три обычных прыжка с паузами, затем простой 10 секунд. Без двойного прыжка и спринта. |
| `GLIDE` | Отдельно 5–10 секунд планера и 10 секунд простоя после посадки. Если неудобно — пропустить. |
| `AXE_TREE` | В безопасном месте 3–5 ударов топором по дереву и простой 10 секунд. |
| `PICK_ORE` | 3–5 ударов киркой по руде, затем простой 10 секунд; записать материал. |
| `PICK_DIRT` | Отдельно три удара киркой по обычной земле. Это контроль вне текущей области мода; можно пропустить. |
| `EMPTY_SWINGS` | По два взмаха топором и киркой в воздух без попаданий. |
| `AGGRO` | Дать врагу заметить персонажа, до 10 секунд не атаковать и по возможности не получать урон. |
| `LOCK` | Включить/выключить захват цели (Tab либо ваша клавиша), по возможности без ударов. |
| `COMBAT` | Получить один удар, один раз ударить врага топором, затем обычным оружием закончить бой. |
| `RECOVER` | После исчезновения активных врагов стоять 30 секунд; затем короткий спринт и один прыжок. |
| `RELOAD` | Главное меню → снова Host того же мира → простой 15 секунд. |

Не смешивайте добычу с недавним боем: первые ресурсные этапы выполняются до
приближения к врагам. Не нужны изменение билда персонажа, новые сохранения,
переустановка игры или второй игрок.

## Что теперь наблюдает мод

- Прежние поля стойки, плюс состояния Actor/locomotion, ID запуска действия,
  последний прыжок и варианты анимации экипировки. Значения — кандидаты;
  они не объявляются названиями конкретных действий по догадке.
- Текущий/максимальный запас из `Stamina`, как в `Enshwick World::vitals`:
  схема и индексы разрешаются из таблицы текущей сборки, проверяются root ID,
  флаг инициализации, количество и границы. `stamina_status=0 current=... maximum=...`.
  Источник алгоритма: `enshwick/enshwick`, коммит
  `535efb4944f99b84de6c5cd12378042b0485d3dc`,
  `crates/enshwick/src/world/stats.rs`; MIT attribution сохранена в
  `third_party/enshwick/LICENSE`.
- Четыре вида событий: `HitEvent`, `HandleEquipmentSlotChangedEvent`,
  `ResourceChangeEvent`, `EntityDiedEvent`. Для попаданий — участники, оружие,
  изменения здоровья/стамины, фракция, типы урона и mining-поля, если доступны.
  Имена/ключи аккаунтов наш мод не пишет. Изменение экипировки сообщает слот,
  а не гарантированное имя выбранного предмета.
- AI-кандидаты: неигровые владельцы `SelectedTargets`, ссылающихся на игрока.
  Дополнительно пишется `enemy_component_status` для `Enemy01BehaviorState`:
  его отсутствие не отключает наблюдение, поскольку setup/runtime типы могут
  различаться. Проверяются 16 элементов по разрешённым размерам/полям
  `TargetInfo`. `player_slot_mask=1` означает slot 0; `primary_slot_mask=1` —
  slot 0 в первом элементе. Это наблюдение цели ИИ, не готовый вердикт «враг
  точно атакует»: фракция тоже требует интерпретации.

`target_observation=lost` означает исчезновение наблюдения, в том числе из-за
смерти/выгрузки/отсутствия компонента, а не доказанный выход из боя.
За опрос сканируются до 4096 владельцев SelectedTargets, до 64 связанных с игроками
отслеживаются между опросами. `query_truncated=1` или `cache_overflow>0`
означают неполноту наблюдения. Опрос остаётся 250 мс, полный снимок примерно
раз в 5 секунд; краткие состояния могут быть пропущены.

События, кроме смертей, выводятся при участии игрока. Смерти сохраняются и для
AI, чтобы сопоставлять исчезающие цели. Лимит — 64 записи событий между
опросами, пропуски отмечаются `event_rate_limit dropped=...`.
`after_step` — последний шаг **опроса**, а не точный шаг самого события.
Временные метки строк загрузчика и поле события `timeStamp`, если оно доступно,
нужны для более точного сопоставления. Поля события записаны сырыми байтами
little-endian; `unavailable` не означает ноль. В `staminaChange` события
`ResourceChangeEvent` восемь байт — пара gain/loss, не одно signed-число.

## Что прислать

После этапа RELOAD закройте игру. Сохраните **новые** файлы
`logs/hitmanrec.stamina-probe_*.log`, `logs/enshwick_*.log` из папки игры,
а также `.build/session-markers.tsv` из репозитория. Не смешивайте их с
первой сессией. Например, положите копии в `logs/session-02/` репозитория
и отправьте в GitHub. Не добавляйте всю `.build/`: там бинарники и загрузчик.
Просмотрите логи перед публикацией — загрузчик может писать личные пути.

Версия 0.2.1 собрана и проверена на fake-host в облаке, но ещё не запускалась
в игре. Если игра начала падать или диагностика вызывает заметные задержки,
закройте её и восстановите предыдущую DLL из резервной копии, сохранив логи.
