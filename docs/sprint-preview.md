# Sprint Preview 0.4.2

Отчёт `sprint-code.tar.gz` позволил найти отдельное накопление расхода спринта
без подмены характеристик и без возврата уже потраченной стамины.

## Проверенная точка кода

EXE SHA-256: `0403981fd2e8ad18bd8c5698dff03c8d505b5a46677832c496db9c645513f2a6`.
Runtime guard проверяет точную таблицу клиента, CodeView GUID/age, адрес
`stamina_depletion_sprint` (RVA `0x2f1000`), пролог и восемь байт патча.
Сам EXE и его дизассемблирование не добавлены в репозиторий.

В RVA `0x2f1505` находятся:

```asm
addss xmm6, [rax]
movss [rax], xmm6
```

Это добавление расхода к накопителю конкретной сущности. R14D содержит
селектор движения, прочитанный в RVA `0x2f1121`. Пропуск разрешается только
для селекторов `0` (наблюдаемый у встроенного сервера) и `4` (Sprint), при совпадении RAX с отражённым полем
`StaminaDepletion.accumulatedValue` подключённого игрока. Селекторы плавания,
ныряния и остальные ветки сохраняют обычные инструкции. Системы прыжков,
инструментов, планера и финального списания не патчатся.

Переход сохраняет флаги, volatile GPR и XMM0–5; callback соблюдает Windows x64
ABI, включая сохранение XMM6–15 и shadow space. Stub размещается в пределах
rel32, после генерации получает RX-права. Enshwick регистрирует патч через
`patch_code`, повторно проверяет исходные байты при включении и отказывает
при конфликте патчей/хуков. Stub после регистрации живёт до конца процесса.
Обновление/отключение этой версии требует перезапуска игры.

## Разрешение бесплатного спринта

На серверном tick читаются игроки и SelectedTargets всех доступных владельцев
этого компонента. Любая цель, ссылающаяся на игрока, блокирует его бесплатный
спринт на 10 секунд после последнего наблюдения. Это консервативный кандидат
боя: нейтральные/дружественные наблюдатели тоже могут блокировать спринт.
Это **не доказанный штатный флаг «в бою»**.

HitEvent немедленно блокирует игрока при входящем попадании или исходящем
попадании по сущности с компонентом Faction. Healing (`flags & 0x4000`)
исключён. Удары по дереву/ландшафту сами по себе не считаются боем.
События обрабатываются до ограничения частоты диагностических строк.

Неизвестная схема события, неполный обход целей, отсутствующий компонент,
неизвестный указатель или другой селектор сохраняют обычный расход.
Разрешение публикуется раз в 250 мс и истекает через 350 мс без обновления;
при смене мира кэш сбрасывается. Hook не обращается к ECS API: только читает
атомарный кэш и системный таймер. Начало агрессии между опросами может дать
до одного интервала задержки; поведение ИИ ещё требует игровой проверки.

## Область готовности

Это первый игровой патч **только спринта**, а не завершение всей исходной
задачи. Двойные прыжки, прыжки по склону, топор и кирка остаются следующим
этапом. Логи прежнего наблюдателя расхода сохранены для их дальнейшего разбора.

Проверены native fake-host сценарии разрешения/запрета, истечение разрешения,
входящие/исходящие попадания, healing и ошибки наблюдения. Машинный stub
исполняется в отдельном Linux x86-64 тесте с Windows ABI callback: обе ветки,
повторные вызовы, передача указателя/селектора и границы генератора.
Сборка Windows DLL проверена отдельно. Игра, Proton, Windows и гость в этой
среде не запускались; работа только у хоста для всех игроков не подтверждена.

Исправление прежнего ошибочного ограничения только значением 4 описано
в [разборе сессии 0.4.1](session-041-analysis.md).
