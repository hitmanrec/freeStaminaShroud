# Результат offline-report-v2 и диагностика стоимости 0.3.0

## Что дал второй отчёт

Та же EXE: SHA-256 `0403981fd2e8ad18bd8c5698dff03c8d505b5a46677832c496db9c645513f2a6`,
GUID `69f0e9573b32c24a8838d3fff550824c`, age 520. Получены 82 диапазона кода,
включая 40 связанных продолжений. Лимит не отбросил ни одного диапазона.
Подтверждены настоящие входы систем `0x2F0600`, `0x2F0A90` и helper
`0x21FBC0`. Наблюдения первого отчёта остаются в `offline-report-analysis.md`.

### Подтверждённый интерфейс helper 0x21FBC0

Windows x64, аргументы по прологу и полному телу:

| Регистр | Роль |
| --- | --- |
| RCX | Указатель на контейнер атрибутов, opaque для нашего observer |
| RDX | Контекст разрешения описателей атрибутов, opaque |
| R8D | Знаковое целочисленное изменение |
| R9D | Идентификатор атрибута |

Функция переносит R8D в EDI, разрешает R9D через `0x123B600`, проверяет
инициализацию контейнера и в `0x21FC29` выполняет ADD в разрешённый слот.
Поэтому отрицательная дельта списывает ресурс. Затем тело пересчитывает
зависимые формулы; это существенно шире одной инструкции вычитания.
Вызовы с `R9D=0x04B6AA8B` относятся к Stamina. На исследованных call sites
результат не используется; функция имеет интерфейс void с четырьмя аргументами.

Ранее найденный прямой дебет `0x2F0C79` обходит этот helper. **Observer helper
не охватывает все расходы**, и отсутствие `cost_trace` не означает отсутствие
расхода. Родительские входы двух систем принимают ECS context в RCX и
перебирают сущности; их имена теперь можно сопоставить через API `system`.

Leaf по `0x135EF30` не имеет записи `.pdata` и не экспортирован: точный метод
округления не установлен. Для наблюдения аргументов общего helper это не
блокер, поскольку observer не рассчитывает и не меняет дельту.

## Что добавлено в 0.3.0

Это по-прежнему диагностика, а не бесплатная стамина. Теперь в отличие от
0.2.x она **регистрирует один наблюдательный hook через Enshwick**, чтобы
видеть вызовы проверенного helper. Файлы EXE на диске не патчатся; loader
временно перенаправляет вызовы в памяти своим обычным механизмом chains.

Observer:

- Всегда вызывает следующий link с теми же четырьмя аргументами; ничего
  не обнуляет, не отменяет, не возвращает потраченную стамину.
- Фильтрует для записи только отрицательные изменения Stamina.
- Получает настоящий адрес возврата через `CALLER_FRAME` до вызова next.
- В рабочем потоке только записывает opaque-указатель, дельту и RVA в
  ограниченную очередь. Не читает ECS, не вызывает logger, не выделяет память
  и не ждёт блокировку. При заполнении/конкуренции запись пропускается,
  **исходный вызов всё равно выполняется**.
- На игровом потоке сопоставляет контейнер с живыми компонентами Stamina
  подключённых игроков и пишет entity ID, входную дельту и RVA возврата.
  Сырые адреса памяти в лог не выводятся.
- Включается только на client EXE с нужным GUID/age, точной таблицей,
  валидным диапазоном кода и совпавшими первыми 20 байтами helper.
  Иначе остаётся только прежняя диагностика. Другие mod hooks, изменившие
  пролог до проверки, также приведут к отказу.

На старте также разрешаются имена `stamina_depletion_sprint`,
`stamina_depletion_glider`, `stamina_depletion_climb_wall`,
`stamina_depletion_finalize`, `stamina_recharge`, `player_control_action_sequence`.
Их найденные RVA записываются без установки дополнительных hooks.

Строки:

```text
cost_trace_hook status=0
cost_system stamina_depletion_sprint status=0 rva=...
sample game=1 step=... cost_trace entity=1 delta=-3 caller_return_rva=... forwarded_unchanged=true
sample game=1 step=... cost_trace_unmatched=... dropped=...
```

RVA записаны десятичными числами. `caller_return_rva` — адрес **после CALL**,
не вход вызывающей функции; 0 означает, что адрес не удалось проверить по
диапазону кода. `delta` — переданный аргумент, не обязательно фактическая
потеря после ограничений/формул или других mods в цепочке. Сопоставлять его
нужно с `stamina_status/current` и событиями.

В очереди до 256 записей. Переполнение/конкуренция учитываются в `dropped`,
несопоставленные контейнеры — в `unmatched` (это могут быть NPC или сущности,
сменившиеся до опроса). При новом мире очередь сбрасывается. Время строки
и `step` относятся к выгрузке очереди, а не точному времени CALL; обычная
задержка до следующего опроса 250 мс. Адрес возврата не различает действия,
если общий вызывающий обработчик обслуживает их все — это предстоит проверить.

## Проверка разработчиком

Проверены охранные условия и отказ при изменённом прологе, точная передача
аргументов, сопоставление игрока, overflow/lock contention. В native stress-test
четыре потока сделали 8000 вызовов: каждый дошёл до original, записи либо
попали в очередь, либо были учтены как пропущенные. DLL собирается в облаке;
реальный hook в Enshrouded ещё не запускался.

## Обновление и короткий следующий захват

Новый офлайн-экспорт EXE **не нужен**. Если готов проверить новую диагностику:
закрой игру, обнови и собери репозиторий прежним способом:

```sh
git pull --ff-only
sh scripts/build-probe.sh
GAME_DIR="$HOME/.local/share/Steam/steamapps/common/Enshrouded"
python3 scripts/install-probe.py --game-dir "$GAME_DIR" --replace
```

Не меняй путь, если твоя библиотека уже настроена иначе: подставь свой.
Launch option и загрузчик прежние. В логе нужны `probe=0.3.0` и
`cost_trace_hook status=0`; если hook отвергнут, пришли старт лога, а не
повторяй сценарий с неработающей трассировкой.

Не переключайся постоянно в терминал: ранее с этим совпадали зависания,
хотя причина не установлена. Достаточно порядка действий, записанного после
выхода из игры, или голосовых заметок на записи. В безопасном месте:

1. Постоять 10 секунд, спринт 5 секунд, постоять 10 секунд.
2. Три двойных прыжка; пауза 10 секунд.
3. Если рядом есть подходящий склон — три прыжка вверх по нему; пауза.
4. Три удара топором по дереву; пауза. Два взмаха в воздух; пауза.
5. Три удара киркой по руде; пауза. Два взмаха в воздух; пауза.

Перемещаться между местами можно: запиши порядок и материал руды. Сражение
и гость для этой короткой проверки пока не нужны. Нужны оба свежих лога и
заметка с порядком действий. Если игра ведёт себя хуже — восстанови прежнюю
DLL из резервной копии, сохранив старт лога. Новая диагностическая функция
не заявлена как проверенная в реальной игре.
