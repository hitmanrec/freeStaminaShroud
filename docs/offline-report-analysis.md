# Разбор первого офлайн-отчёта EXE

Отчёт получен архивом в чате. Исследуется только переданный текст кода,
EXE в облаке отсутствует. Исходный архив/дизассемблирование не добавлены в Git;
ниже сохранены выводы и минимальные ссылки на RVA для воспроизводимости.

Идентичность файла:

- SHA-256 EXE: `0403981fd2e8ad18bd8c5698dff03c8d505b5a46677832c496db9c645513f2a6`.
- CodeView GUID (memory order): `69f0e9573b32c24a8838d3fff550824c`, age 520.
- Отпечаток совпадает с тремя пользовательскими сессиями, build `26320373`.
- 31 упоминание корня атрибута стамины; 25 различных диапазонов `.pdata`.
  Все 25 запрошенных диапазонов экспортированы без лимитного усечения.
- Литеральные хеши двух компонентов depletion не найдены в исполняемых
  секциях. Это не означает отсутствия компонентов или их систем.

## Реальное списание, не только чтение

### Float-накопитель → целочисленный дебет

В диапазоне `0x2F0ACE–0x2F0CC7` видны:

1. Проверка порога накопителя `[rdi]` и инициализации атрибута.
2. Вызов `0x135EF30` с float из `[rdi]`, результат сохраняется в `xmm6`.
   Точное округление этой вспомогательной функции пока не установлено.
3. `0x2F0BFA`: вычитание `xmm6` из накопителя, запись остатка обратно.
4. Разрешение корня Stamina `0x04B6AA8B` через `0x123B600`.
5. `0x2F0C72`: перевод `xmm6` в integer.
6. **`0x2F0C79`: `sub DWORD PTR [r8+rcx*4],eax`**, затем вызов `0x2357E0`.

Это доказанное по коду место арифметического списания из слота стамины.
Но источник накопления, принадлежность накопителя компоненту StaminaDepletion
и соответствие спринту/планёру/другим действиям ещё не доказаны. Отключать
этот SUB глобально нельзя: он не содержит проверенного признака действия.

### Накопление стоимости движения

В диапазоне `0x2F0640–0x2F0A80` код обрабатывает три float-компоненты вектора,
масштабирует их, вычисляет сумму квадратов и корень, применяет коэффициенты
и в **`0x2F09F6–0x2F09FA`** прибавляет результат в float-память `[rax]`.
В этой ветке разрешаются Stamina и другой атрибут `0xB8388248`.

Это сильный кандидат пути накопления расхода, связанного с движением, но
название второго атрибута и семантика контекста не получены. Константы по
RIP-relative адресам в отчёт не вошли; нельзя выдавать предполагаемые
единицы/коэффициенты за измеренные значения. Этот код не является прямым
вычитанием текущей стамины.

### Другие дебеты

| RVA | Наблюдение | Чего ещё нет |
| --- | --- | --- |
| `0x2CA2B7` | SUB из разрешённого слота Stamina, значение берётся со стека; далее `0x2357E0` | Назначение действия/события |
| `0x223AB8–0x223B0A` | Стоимость меняет знак и передаётся в `0x21FBC0` с корнем Stamina; рядом аналогичный путь Mana | Тело helper и контекст действия |
| `0x2C97DE–0x2C97F4` | Отрицательная стоимость Stamina передаётся тому же helper `0x21FBC0` | Нельзя пока назвать это прыжком или инструментом |
| `0x4290D8` | После проверки Stamina выполняется прямой SUB и последующая обработка описателя | Происхождение аргументов и вызывающая игровая логика |
| `0x3602F7` | Из одного атрибута Stamina вычитается значение, ранее прочитанное из другого контекста | Возможен перенос/особый эффект; это не подтверждённая точка обычной стоимости |

## Отделённые пути

- `0x27CD8C–0x27CF66`: чтение текущего/max Stamina и запись ограниченных значений
  в WORD-поля сетевой структуры. Это не отмена расхода.
- `0x23DD3E–0x23E4D1`: временные/пороговые проверки, float-остаток и **ADD**
  к Stamina в `0x23E3E3`, затем `0x2357E0`. По форме это кандидат регенерации,
  а не общий дебет. Его нельзя подавлять вместе с расходом.
- `0x21FA10`, `0x24E060`, `0x33D27C`: видны проверки/чтения доступной стамины;
  это не доказанные источники стоимости.
- `0x12497B0`, `0x1249E10`: общие диспетчеры/доступ к компонентам по хешу.
  Перехватывать их глобально ради стамины слишком широко.

Остальные диапазоны пока не получили надёжных семантических имён.
Никакие адреса из этого документа не установлены как игровой hook.

## Ограничение первого экспортера

Некоторые диапазоны `.pdata` начинаются уже с обращения к установленному
кадру стека (`rbp`, сохранённые регистры), без полного пролога. Есть переходы
за пределы отдельного экспортированного диапазона. В Windows unwind-таблице
могут находиться части/продолжения одной функции, а не отдельные callable
entry points. Первый скрипт называл их `function-*`, что было слишком сильной
интерпретацией.

Экспортер расширен: сохраняет chained unwind metadata, родительские и
связанные диапазоны, а также умеет включать helper по `--focus-rva`.
Так можно получить недостающий контекст без игры и без передачи всей EXE.

## Следующий необходимый статический пакет

Нужны тела общих helper и исходный контекст уже найденных дебетов. Обновлённый
скрипт можно запустить одним офлайн-вызовом:

```sh
git pull --ff-only
GAME_DIR="$HOME/.local/share/Steam/steamapps/common/Enshrouded"
python3 scripts/inspect-game.py --exe "$GAME_DIR/enshrouded.exe" \
  --out .build/offline-report-v2 --max-functions 128 \
  --focus-rva 0x21fbc0 --focus-rva 0x2368a0 \
  --focus-rva 0x2357e0 --focus-rva 0x24e3a0 --focus-rva 0x135ef30
tar -czf .build/offline-report-v2.tar.gz -C .build offline-report-v2
```

Это адреса реально вызванных функций из переданного кода, а не предполагаемые
смещения другой версии. Запускать игру, повторять сценарий и обновлять DLL
диагностики для этого не требуется. Пакет нужен для идентификации действий,
владельца-игрока и правил округления до написания точечного перехвата.
