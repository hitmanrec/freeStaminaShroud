# 0.5.1: тип запрошенного прыжка вместо предыдущего состояния

Источник: оба лога `2026-11-03_19-09-30` в `logs/`.
Пользователь подтвердил спринт и отсутствие расхода топора в воздухе/по дереву;
первые двойные прыжки и подъём по склону ещё расходовали стамину.

Путь `0x2c97f9` зарегистрировал 50 расходов. В 34 случаях они обнулены
(reason 2, прочитаны типы 1/2/5). Остальные 16 сохранили стоимость:
13 раз -10 и 3 раза -15, все с **reason 8, detail 0**.
Это отказы классификатора типа, а не боя, просроченного разрешения или потока.
Топор подтверждён 16 обнулёнными стоимостями -3 для item 1978632298.
Другие item ID в логе без дополнительной привязки не объявляются киркой
или конкретным боевым оружием.

Ошибка 0.5.0: DynamicLocomotion.jumpType отражает уже применённое/предыдущее
состояние. В момент списания оно может ещё быть Invalid (0), а после серии
прыжков становится известным. Поэтому первые прыжки не классифицировались.

В обоих проверенных EXE путь прыжка делает запись:

- RVA `0x2c9684`: берёт тип запрошенного прыжка из временного результата;
- RVA `0x2c9695`: записывает байт в ActorInput.externalTriggerJumpType,
  отражённый offset `0x179` (377);
- затем рассчитывает стоимость и вызывает helper; return RVA `0x2c97f9`.

Соседняя запись времени в offset `0x180` соответствует
ActorInput.externalTriggerJumpTime. Поле запроса записано до списания,
поэтому в 0.5.1 классификатор читает именно его через живой серверный компонент.
Ни значение 0, ни все неизвестные прыжки не становятся бесплатными.
Список наземных типов и условия боя остаются прежними.

Добавлен guard окна `[0x2c9684,0x2c969b)` (23 байта), FNV-1a
`0x75f3353c`: оно совпадает в отчётах /520 и /205. Проверки вызывающего
пути, атрибута, компонента игрока, потока и срока разрешения сохранены.

Native regression использует разные компоненты ActorInput и DynamicLocomotion,
проверяет разрешённый запрос при старом Invalid и отказ для нового исключённого
запроса при предыдущем допустимом типе. Инициализация отражения также проверяется:
должен запрашиваться ActorInput.externalTriggerJumpType, не DynamicLocomotion.

Следующий короткий тест после обновления/пересборки/установки 0.5.1:
первый двойной прыжок после загрузки, ещё один после спокойного стояния,
затем несколько одиночных прыжков вверх по склону. Достаточно одного игрока.
Ожидается `action_reason=2 applied_delta=0` для нужных расходов вне боя.
Спринт и инструментальная часть по результатам этого исправления не изменены.
