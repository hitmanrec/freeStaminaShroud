# Gameplay Preview 0.5.1: прыжки и инструменты

Версия добавляет изменение прямых расходов к уже проверенному патчу спринта.
Инструменты не разделяются по цели: взмах по воздуху, земле, дереву, руде
или существу рассматривается одинаково, в том числе в бою.

## Правила

- Спринт: прежнее поведение, бесплатно вне наблюдаемого боя.
- Наземные прыжки, включая двойные и по склону: бесплатно вне наблюдаемого
  боя. В бою возвращается обычная стоимость. Обычный бесплатный прыжок сам
  по себе не требует нового списания и не получает дополнительной обработки.
- Топор для рубки и кирка: проверяется текущий предмет категории Tools (3)
  и анимация TwoHanded (4). Их прямые расходы подавляются независимо от боя.
  Другие инструменты, если игра относит их к той же категории и анимации
  и проводит стоимость через тот же вызов, также подпадают под это правило.
  Боевые предметы категории Weapons (2), включая двуручные, не подпадают.
- Плавание, планер, атаки обычным оружием, мана, прочность, расход боеприпасов
  и другие атрибуты сохраняют игровые правила.

Это экспериментальная реализация; новая часть ещё не проверена в самой игре.
Гостям по-прежнему сначала ничего не устанавливать. Действие на авторитетный
компонент гостя и поведение его клиента необходимо подтвердить отдельно.

## Как устроено

Используется уже установленный CALLER_FRAME hook helper `0x21fbc0`.
На проверенных сборках /520 и /205 проверены следующие вызовы:

| Назначение | Return RVA | Проверяемое окно перед возвратом | FNV-1a |
| --- | --- | --- | --- |
| Стоимость действия | `0x223b0f` | `[0x223af7,0x223b0f)` | `0xdec87622` |
| Стоимость прыжкового пути | `0x2c97f9` | `[0x2c97d0,0x2c97f9)` | `0xec1d643e` |

Также проверяется запись запроса прыжка `[0x2c9684,0x2c969b)`,
23 байта с FNV-1a `0x75f3353c`. Эти окна совпали в обоих отчётах. Сохраняются проверки build fingerprint,
стороны, prologue helper и диапазона .text. Для других вызывающих путей и
других корневых атрибутов аргументы передаются без изменения.

Подавление разрешается только для отрицательной дельты Stamina `0x04b6aa8b`
и точного указателя авторитетного компонента подключённого игрока. Указатели
сопоставляются со slot/entity на серверном tick; разрешение истекает через
350 мс без обновления и сбрасывается при смене мира.

Перед чтением ECS проверяется реальный GetCurrentThreadId против потока
последнего серверного tick. На worker/client thread выполняется обычный
вызов без чтения компонентов. На подтверждённом серверном потоке компонент
Stamina повторно запрашивается и сравнивается с аргументом helper. Старые
указатели из кэша никогда не разыменовываются.

Для инструмента SlotSelection.actionItem.itemId читается **в момент вызова**,
категория запрашивается через item_info, а анимация — из EquipmentAnimationSets.
Не используются фиксированные session PIDE, величина стоимости -3/-4 или
одно значение анимации. Это сохраняет расход боевого двуручного оружия при
быстром переключении с инструмента между диагностическими tick.

Для прыжка используется разрешение/задержка того же SprintPlayer и живое
поле ActorInput.externalTriggerJumpType, записанное игрой до списания.
DynamicLocomotion.jumpType больше не используется: оно могло ещё содержать
предыдущий тип или Invalid. [Разбор и исправление 0.5.1](session-050-jump-fix.md). Принимаются Default (1), DoubleDefault (2),
DoubleSprint (3), DoubleMountain (4), Sprint (5), Mountain (14), Slide (15).
Submerged, Glider, HookSwing, Attack и неизвестные типы не обнуляются.
Семантика названий взята из отражённых типов того же исследованного EXE;
запись запроса до списания проверена в обоих отчётах; игровой эффект исправления
0.5.1 ещё нужно подтвердить.

При разрешении оригинальный helper вызывается с delta=0. Игра сама продолжает
действие и обработку остальных атрибутов. Отложенного возврата уже потраченной
стамины, замены всей функции или постоянной записи характеристик нет.
Проверки доступности действия, которые игра могла выполнить раньше этого
списания (например, возможность начать действие при уже пустой стамине),
этим перехватом не отключаются.

## Проверка на машине игрока

Закрыть игру, выполнить `git pull --ff-only`, `sh scripts/build-probe.sh`,
переустановить через `scripts/install-probe.py --game-dir … --replace`.
ID мода, имя DLL и путь установки сохранены; в меню он теперь называется
**Free Stamina Shroud - Gameplay Preview**.

В свежем логе должны быть `probe=0.5.1`, `sprint_patch_registered status=0`,
`cost_trace_hook status=0`, `action_cost_guard status=0` и `action_rules`.
Отклонённые проверки не обходить: сохранить оба свежих лога.

Первый прогон можно сделать одному:

1. Без врагов: 3 двойных прыжка с паузами; затем несколько прыжков по склону.
2. Топором: несколько ударов по дереву и взмахов в воздух. Киркой: несколько
   ударов по руде/земле и взмахов в воздух. Ожидается отсутствие расхода.
3. Переключиться с инструмента на обычное боевое оружие, сделать несколько
   ударов. Их расход должен сохраниться, особенно у двуручного оружия.
4. Привлечь волка: спринт и двойной прыжок должны расходовать стамину,
   взмахи топором/киркой — оставаться бесплатными. Необязательно бить врага
   инструментом, если это неудобно. Уйти и подождать 15 секунд, снова прыгнуть.
5. Один раз использовать планер: его расход должен остаться обычным.

Сохранить оба лога и порядок действий. Не нужны длинные повторные сессии.
После одиночной проверки можно повторить ключевые действия гостем без мода,
пока хост стоит, по [правилам совместной диагностики](guest-test.md).

## Диагностика

Строка `cost_trace` теперь содержит исходную `delta`, `applied_delta`,
`forwarded_unchanged`, `action_reason` и `action_detail`, плюс entity и RVA.
`forwarded_unchanged=false applied_delta=0` означает реальное подавление
стоимости, не только разрешение в кэше.

| action_reason | Смысл |
| --- | --- |
| 0 | Неизвестный путь или отключённая новая часть: обычный расход |
| 1 | Бесплатное действие инструмента |
| 2 | Бесплатный наземный прыжок |
| 3 | Нет подтверждённого серверного потока: обычный расход |
| 4 | Нет совпадения живого компонента игрока |
| 5 | Истёк кэш игроков |
| 6 | Предмет/категория/анимация не подходит или недоступны |
| 7 | Нет свежего разрешения прыжка вне боя |
| 8 | Тип прыжка неизвестен, исключён или поле недоступно |

action_detail для предмета — item ID, для прочитанного jumpType — его значение.
Дополнительные чтения выполняются на серверном потоке, вывод — при дренировании
ограниченной очереди на tick; незнакомые случаи не становятся бесплатными.

В облаке проверены реальные функции detour и политики через fake host:
живое переключение инструмент → боевое оружие, бой/независимость игроков,
неизвестные указатели/атрибуты/вызовы, worker thread без ECS, срок разрешения,
типы прыжков, ошибки API, сохранение оригинального вызова с нужной дельтой.
Отдельно пройдены AddressSanitizer/UBSan и сборка Windows DLL. Запуска самой
игры/Proton в облаке не было.
